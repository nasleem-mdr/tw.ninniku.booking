# i18n Implementation Plan — tw.ninniku.booking

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Replace all hardcoded user-facing strings in the booking plugin with iDempiere `Msg.getMsg()` calls, supporting English and Traditional Chinese (zh_TW) via the standard AD_Message database table.

**Architecture:** A single SQL migration seeds all message keys. Java classes call `Msg.getMsg(ctx, "BK_xxx")` directly. `BookingVM` builds a `Map<String,String> labels` at construction time and exposes it to ZUL via `@load(vm.labels.key)` bindings.

**Tech Stack:** iDempiere `org.compiere.util.Msg`, PostgreSQL `nextid()`, ZK MVVM `@load` binding, SQL migration script.

## Files Changed

### New: `migration/i18n_setup.sql`

Follows the same pattern as `tw.idempiere.requestkanban/migration/i18n_setup.sql`:

1. `DELETE` any existing `BK_` rows from `AD_Message_Trl` and `AD_Message` (idempotent re-run).
2. `INSERT INTO AD_Message` — one row per key, English `MsgText`, using `nextid('AD_Message','N')`.
3. `INSERT INTO AD_Message_Trl` — zh_TW rows for every key using a single `CASE Value WHEN ... END` block.

`MsgType` values: `'I'` for informational labels, `'E'` for error messages.

### Modified: `BookingValidator.java`

Replace 6 hardcoded `String` literals in validation checks:

```java
// Before
throw new BookingValidationException("Name is required.");

// After
throw new BookingValidationException(Msg.getMsg(Env.getCtx(), "BK_NameRequired"));
```

`Env.getCtx()` is thread-local and safe to call statically. No method signature changes.

Keys to replace: `BK_NameRequired`, `BK_StartRequired`, `BK_EndRequired`, `BK_StartBeforeEnd`, `BK_WeeklyEndRequired`, `BK_WeeklyEndAfterEnd`.

### Modified: `BookingService.java`

Replace 4 hardcoded strings using the existing `ctx` field:

```java
// Before
throw new AdempiereException("時間重疊: " + range);

// After
throw new AdempiereException(Msg.getMsg(ctx, "BK_TimeOverlap") + ": " + range);
```

Keys to replace: `BK_PermissionUpdate`, `BK_PermissionDelete`, `BK_TimeOverlap`, `BK_TimeOverlapUpdate`, `BK_FailedLoad`, `BK_ErrorSaving`.

### Modified: `BookingVM.java`

Add `loadLabels()` called from the constructor, and expose `getLabels()`:

```java
private final Map<String, String> labels = new LinkedHashMap<>();

private void loadLabels() {
    Properties ctx = Env.getCtx();
    labels.put("booking",      Msg.getMsg(ctx, "BK_Booking"));
    labels.put("refresh",      Msg.getMsg(ctx, "BK_Refresh"));
    labels.put("resource",     Msg.getMsg(ctx, "BK_Resource"));
    labels.put("week",         Msg.getMsg(ctx, "BK_Week"));
    labels.put("day",          Msg.getMsg(ctx, "BK_Day"));
    labels.put("timeline",     Msg.getMsg(ctx, "BK_Timeline"));
    labels.put("today",        Msg.getMsg(ctx, "BK_Today"));
    labels.put("newBooking",   Msg.getMsg(ctx, "BK_NewBooking"));
    labels.put("editBooking",  Msg.getMsg(ctx, "BK_EditBooking"));
    labels.put("name",         Msg.getMsg(ctx, "BK_Name"));
    labels.put("memo",         Msg.getMsg(ctx, "BK_Memo"));
    labels.put("start",        Msg.getMsg(ctx, "BK_Start"));
    labels.put("end",          Msg.getMsg(ctx, "BK_End"));
    labels.put("weekly",       Msg.getMsg(ctx, "BK_Weekly"));
    labels.put("repeatUntil",  Msg.getMsg(ctx, "BK_RepeatUntil"));
    labels.put("save",         Msg.getMsg(ctx, "BK_Save"));
    labels.put("delete",       Msg.getMsg(ctx, "BK_Delete"));
    labels.put("cancel",       Msg.getMsg(ctx, "BK_Cancel"));
}

public Map<String, String> getLabels() { return labels; }
```

ZK EL resolves `vm.labels.save` → `labels.get("save")` automatically via Map property access.

## Installation

Run `migration/i18n_setup.sql` against the iDempiere PostgreSQL database once after deploying the plugin. The script is idempotent — it deletes and re-inserts `BK_` rows, so it is safe to re-run after updates.

## Out of Scope

- JavaScript `confirm()` and validation strings — remain in English.
- Console/debug log messages — remain in English.
- Adding further languages beyond English and zh_TW — handled through the standard iDempiere AD_Message UI without code changes.
